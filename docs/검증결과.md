# 검증 결과

- TypeScript 빌드: 통과.
- DB 없이 실행하는 HTTP API 테스트: 7개 통과.
- 실제 MySQL 통합 검사: 3개 통과. 회원별 필터링, 최신순 정렬, 응답 필드와 404 확인.
- DB 초기화: member/rating/favorite 테이블 생성, 수현(1번)·민서(2번)와 평점 3건 입력 완료.
- 브라우저에서 실제 API 연결 검사: 세 버튼 모두 HTTP 200 확인.
  - 수현 닉네임: `available: false`.
  - noco@umc.com 이메일: `available: false`.
  - 1번 회원 평점: ratingId 2 → 1, movieId 155 → 550 순서.
- CORS 설정 전: 서버 자체는 HTTP 200이나 허용 헤더가 없고, 브라우저 fetch는 실패하는 것을 확인.
- CORS 설정 후: 같은 브라우저 화면에서 세 API 정상 응답 확인.
- 화면 캡처: `cors-before.png`, `cors-after.png`, `ratings-result.png`.
- Postman: 가져오기용 컬렉션 제공. Postman 앱에서 직접 요청/캡처하는 단계는 사용자가 진행할 수 있도록 README에 설명.

자동 HTTP 테스트는 중복 확인, 한글 경로, DTO 필드, null/날짜 처리, 빈 평점,
없는 회원의 404, 숫자가 아닌 회원 번호의 400, CORS와 사전 OPTIONS 요청을 확인했습니다.
Node fetch의 검증과 실제 브라우저의 CORS 적용 검증은 구분합니다.

화면은 사용자 요청에 따라 CSS 없이 HTML 입력창·버튼·fetch 함수만 있는 간이 프론트로 구성했습니다.

## 해결한 연결 문제

사용자가 접속 정보를 상위 폴더 `D:/be/study/.env`에 입력했으나,
실제 앱은 `D:/be/study/movie/.env`를 읽고 있었습니다.
입력한 계정 설정을 앱의 .env에 반영한 뒤 MySQL 연결과 초기화가 정상 완료되었습니다.
실제 접속 비밀번호는 이 문서나 전체 코드 보고서에 포함하지 않습니다.

검증 환경은 Node.js 22.20.0입니다. 패키지 설치 시 Nest CLI의 Angular DevKit 의존성에서
Node 엔진 경고가 있었으며, 이 환경에서 빌드와 위 HTTP 테스트는 통과했습니다.
